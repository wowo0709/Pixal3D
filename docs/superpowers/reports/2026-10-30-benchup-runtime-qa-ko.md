# BenchUp 렌더 CPU 사용 점검

Blender에 `-t 2`를 지정했어도 glTF import와 mesh 처리 중 다수의 CPU 코어를 동시에 사용하는 현상이 관찰됐다. 다른 작업에 대한 영향을 줄이기 위해 이 BenchUp 실행의 Blender에만 물리 GPU별 최대 16개 CPU 코어 범위를 적용했다. 메트릭, mesh, 카메라, 렌더 설정과 GPU 범위는 변경하지 않았다.

동일한 TRELLIS.2 `batman__render_0006` 시험 작업을 GPU 2에서 제한 전후로 렌더해 RGBA 픽셀 전체를 비교한 결과, 512×512×4의 모든 픽셀이 일치했다. PNG 파일 자체의 SHA-256은 서로 달랐으므로 검증은 디코딩된 픽셀 기준으로 기록한다. 이 단일 사례 검사는 전체 모델·사례에 대한 동등성 증명은 아니다.

## 렌더링 면 수 상한의 표면 진단

TRELLIS.2의 `backhoe__render_0009` 한 사례에서 Blender 4.2.3 렌더링 단계의 100만 면 상한을 재현했다. 1,352,391면에서 1,000,000면으로 단순화한 전후 표면을 각각 400,000점 샘플링해 양방향 최근접점 거리를 비교한 결과, 99백분위는 각각 0.0037213과 0.0037392로 진단 기준 0.01 이하였다. 샘플 간 거리는 연속 표면까지의 최근접 거리의 상한이며, 단일 mesh의 geometry 검사이므로 다른 사례나 텍스처의 보존을 보증하지 않는다. Target GT는 사용하지 않았다. 세부 결과는 file4의 `benchup/reports/render-budget-surface-qa-v1.json`에 보관한다.
