## 04:00 KST 사용자 범위 조정

[최소 완료 계획](2026-10-28-minimal-no-retrain-completion-plan-ko.md)에 따라 새 학습·새 모듈 탐색·6개 내부 행 전체의 GT-scale-free 재생성은 하지 않는다. 이미 있는 oracle-scale 6행 TEST508와 DEV ablation 결과를 조건을 명시한 내부 표로 활용하고, 주 외부 비교에는 고정 체크포인트의 **Ours V1·Selected 두 행만** 새 GT-scale-free 출력으로 연결한다. 공식 RGB1/외부 baseline 생성·평가 작업은 이미 진행 중인 것을 끝까지 사용한다. 동일 성공 교집합의 FID/KID 등 필수 채점만 다시 수행한다. [기존 내부 표 caption](../paper/final-results/main-table.tex)에도 M1 유래 객체 scale이 생성에 제공된 사실을 명시했다.

SS가 실제 시작되거나 종료됐다는 주장은 아니다.

## 03:55 KST 공식 RGB1 native-scale 실패와 공통 성공 집합 수정

공식 Pixal3D `T1+C`, scale 키 생략, seed0·1024 생성이 244개 성공 뒤 245번째에서 **native sparse tensor가 비어 Shape SLat 단계에서 종료**됐다. 실패 사례의 원본 traceback은 node16의 `no-scale-official1024/cases/shard002_6f4509a0f0714891ab41b08cd2848315_d2_fast300fpssupplyv1_balanced_JN_L_target08/failure.json`에 보존했다. 이 사례는 기존 외부 7법 common502에 포함된다. 508개 전부 성공을 전제한 기존 surface/export watcher와 공식 render watcher는 오류를 내고 종료했으며, 이는 결과 완료가 아니다.

생성 코드는 알려진 이 모델 고유의 empty-sparse 예외에 대해서만 checksum이 있는 `failure-receipt.json`을 남기고 다음 사례로 계속하도록 수정했다. 기존 244개 성공 산출물은 SHA 재검증 후 재사용한다. node16 GPU7 생성 PID `2972599`를 재개했고, 새 surface/export watcher PID `3016320`/`3016321`, 로컬 공식 렌더 watcher PID `532893`, node16 공통 평가 watcher PID `3029573`을 연결했다. 각 단계는 508회 **시도 완료** 뒤 `외부 common502 ∩ 공식 성공` 집합을 명시적으로 만들고 그 실제 개수만 평가한다. 실패한 사례를 성공으로 보정하거나 seed를 바꾸지 않는다. 최종 전체 모델 표도 모든 모델의 공통 성공 교집합에서 다시 계산해야 한다. 공식 실패가 추가될 수 있어 현재 교집합 크기는 아직 확정되지 않았다.

03:58 KST 평가기 경로 보완: 이전 평가 watcher PID `3029573`은 대기 단계에서 종료하고, **최종 9방법 동일 집합 평가** watcher PID `3125579`로 교체했다. 외부 7법의 기존 +M0 평가기 binding을 공식 RGB1 raw/+M0 binding과 [명시적 공통 성공 집합](../../../experiments/deformnext_retargeting/merge_common_success_evaluator_manifests.py)에서 합친 뒤, 모든 방법의 source9/10 learned metric·FID/KID·surface CD/F를 **동일한 N**에서 한 번에 계산한다. target8 PSNR/SSIM/M-IoU도 외부 7법 및 공식 raw/+M0를 같은 N에 다시 집계한다. 외부 7법의 raw source learned metric·FID/KID는 별도 동일 N 재평가가 아직 필요하다. 따라서 이 watcher의 완료만으로 raw/+M0 주 표 전체가 완성되는 것은 아니다.

카메라 제공 계약은 camera-to-world와 FOV, 획득 시 알려진 거리까지만 포함한다. 외부에서 정답 `mesh_scale`을 주지 않는다. 공식 Pixal3D RGB1은 생략 시 native default `1.0`을 쓰고, Ours는 같은 기본값 대조군과 이미지 내부 추정 후보를 모두 DEV에서 비교한다. source M0와 target M1의 사례별 mesh scale은 생성 입력이 아니다. VAL에서 기존 checkpoint의 SS/Shape/PBR, 렌더 및 metric 변화를 작은 matched subset으로 확인한다. 통과하면 기존 학습 checkpoint를 유지하고 필요한 arm의 TEST 예측만 재생성·공통 평가한다. 변화가 커서 재학습이 필요하면 해당 이유와 추가 시간을 VAL 실측으로 산정한다. 현재 M1-scale Ours 6행의 공통 평가는 진단으로 완료하되 주 표에 그대로 옮기지 않는다.

입력 구분: 공식 Pixal3D RGB1 baseline은 target RGB 1장과 해당 카메라를, multi-view zero-shot 및 Ours는 target RGB와 source RGB들, 각 view의 카메라를 받는다. `mesh_scale=1.0`은 투영 좌표계의 기본 정규화일 뿐 이미지 조건부 생성 능력을 끄지 않는다. 카메라 제공 주 표에서 외부 pose 추정기는 사용하지 않으며, 카메라 미제공 참고 실험에서는 공식 MoGe 추정 경로를 별도로 허용한다. 이미지에서 추론한 크기와 생성 후 M0 Sim(3) 후처리는 입력으로 정답 scale을 주는 것과 구별한다.

구현 확인: `pixal3d/datasets/deformnext.py`의 latent 로더는 archive 내부 `mesh_scale`이 manifest 값과 일치하는지 검사하고, `projection_maps.py`도 voxel→pixel 주소 계산에 scale을 직접 사용한다. 따라서 Ours에서 manifest의 숫자만 `1.0`으로 바꾸고 기존 projection sidecar를 그대로 쓰는 것은 유효하지 않다. VAL SS 진단은 기존 GT latent를 **점수 label로만** 유지하고 sampler의 inference pack에서 `x_0`을 제거한 뒤, scale `1.0`과 그에 맞춰 다시 계산한 ray patch grid를 모델에 전달한다. full cascade에서는 target GT latent/support를 생성 입력으로 읽지 않는지 별도 검사한다. 재학습이 필요한 경우 label/cache recipe를 다시 정의한다.

카메라 추정/미제공 실험은 논문의 일반화 주장에 필요할 때 보조 sensitivity로만 한다. 주 표를 위해 Ours의 camera-free 경로를 새로 만들거나 모든 arm을 camera-free로 다시 학습하지 않는다.

## ICP/Sim(3) 정합의 역할

이 결정의 목적은 카메라 pose/FOV 활용 효과와 **외부 정답 scale 제공 효과**를 분리하는 것이다. 주 평가에서 정답 객체별 scale은 제공하지 않는다. 공식 Pixal3D는 native default `1.0`, Ours의 개발 중 후보는 이미지 내부 추정값을 사용하므로, 비교표에는 이 차이를 표시하고 Ours native1 대조군도 포함한다. 내부 scale 추정 모듈의 효과는 동일 Ours checkpoint·입력에서 별도 비교한다. 모든 방법의 생성이 끝난 뒤 입력 source M0 mesh로 구한 Sim(3) 변환을 동일하게 적용하는 paired 후처리 실험을 진행한다. 논문 표에는 각 방법의 카메라 메타데이터 수용/실제 사용 여부와 M0 후처리 여부를 표시한다. target M1 mesh에서 계산한 사례별 `mesh_scale`을 생성에 주었던 기존 수치는 GT 정보 누출 진단으로 격리한다.

모든 방법의 raw 출력은 제공된 카메라의 동일 world frame에서 그대로 채점한다. 모델별 GLB 축 변환과 고정 단위 변환은 저장된 원래 출력 포맷의 결정적 변환으로 유지한다. TEST M1 GT surface/렌더에 맞춰 scale·rotation·translation을 최적화하면 정답을 사용한 oracle metric이 되어 주 task의 위치·크기 정확도까지 지워진다.

**추가 실험: 입력 source M0 기준 Sim(3) 후처리.** 다른 baseline의 생성 출력도 입력으로 사용 가능한 원본 source M0 mesh에 정합한다. 모든 방법에 동일한 M0 후처리와 TEST508 공통 성공 사례를 적용하고, `raw`와 `+M0 Sim(3)`의 paired CD/F@0.02를 모두 보고한다. 정합 변환은 M0와 출력 형상으로만 구하며 target M1의 geometry, depth, render, mask 또는 metric을 최적화에 사용하지 않는다. 변형 영역에 의한 편향을 줄이기 위해 부분 중첩에 강한 trimmed symmetric ICP를 사용하고, 정합 전후 M0 적합도, scale 및 실패 사례를 기록한다. 매개변수는 VAL 또는 사전 고정 규칙으로 정하고 TEST 점수를 보고 고르지 않는다. 2D 지표까지 비교하려면 `to_world_aligned = T_M0_ICP × to_world_native`로 **변환된 textured output을 같은 camera/renderer로 재렌더**한 뒤 PSNR/SSIM/M-IoU/LPIPS/DreamSim/CLIP/FID/KID를 재계산해야 하며, 변환되지 않은 기존 PNG를 재사용할 수 없다. 추가 M0 입력 권한은 `+M0` 열과 본문에 표시한다.

M0 정합은 변형된 M1과 다른 형상에 맞추므로, 변형이 넓은 사례에서는 올바른 편집 위치까지 틀 수 있다. 따라서 raw와 정합 후 수치를 함께 보여 주고, 한 방법에만 후처리를 적용한 숫자를 다른 방법의 raw 숫자와 같은 조건인 것처럼 비교하지 않는다. scale 미제공 Ours 및 공식 Pixal3D 출력이 준비되면 같은 M0 정합을 적용해 완전히 짝지어진 비교를 만든다. M1 GT에 정합한 oracle 실험은 이 M0 후처리와 구별하며 주 표에는 싣지 않는다. 무엇보다 출력 후 M0 정합은 생성 시 이미 사용한 M1-derived `mesh_scale` 입력 누출을 제거하지 못한다.

### VAL32 SS scale 민감도 진단

V1·RETARGET·SELECTED의 **동일 checkpoint·동일 VAL32·동일 seed**로 scale 입력을 제거한 실행과 기존 M1 유래 scale 실행을 각각 완료했다. target SS latent는 생성 조건에서 제거하고 점수 label로만 썼다. 기존 latent 격자에서 직접 비교한 voxel IoU는 scale 미제공 시 `0.2705/0.2705/0.2693`, 기존 scale 사용 시 `0.4336/0.4405/0.4447`이다. 서로 다른 정규화 좌표를 같은 격자로 대조한 수치이므로 주 품질 지표로 쓰지 않는다.
